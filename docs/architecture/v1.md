# Type Bharat Architecture v1

Status: Stable

Version: 1.0

---

# Philosophy

Type Bharat is a data-driven multilingual platform.

Languages are configuration, not implementations.

Adding a new language must not require architectural changes.

---

# Principles

- One shared architecture
- Dynamic routing
- Shared UI components
- Shared metadata generation
- Shared SEO
- Shared language registry
- Zero duplicated pages

---

# Language Structure

Every language contains:

```
data/language/<language>/

alphabet.ts

faq.ts

language.ts
```

No additional files unless approved.

---

# Registry

The registry is the single source of truth.

```
lib/languages/registry.ts
```

All language discovery originates from the registry.

---

# Routing

Dynamic routes only.

Typing

```
/typing/[language]
```

Learn

```
/learn/[language]
```

No language-specific pages.

---

# Metadata

All metadata must be generated using shared helpers.

No page should manually create metadata.

---

# Components

Components must be reusable.

Language-specific UI components are not permitted unless the script requires unique rendering behavior.

---

# Language Contract

Every language must provide:

- Identity
- Alphabet
- FAQ
- Typing Content
- Learn Content
- Labels
- SEO
- Capabilities

---

# Testing

Every language must pass:

- Contract Tests
- Integration Tests
- Manual QA

before merge.

---

# Pull Request Requirements

Every PR must satisfy:

- TypeScript
- ESLint
- Tests
- Build
- Manual QA

---

# Non-Goals

The following are not allowed during language integration:

- Architecture redesign
- Folder restructuring
- Route duplication
- Metadata duplication
- Component duplication
- Shared type modifications

---

# Future Expansion

The architecture is designed to support:

- OCR
- Speech to Text
- Text to Speech
- Translation
- AI Features
- Browser Extension

These capabilities must integrate into the existing architecture rather than introducing parallel systems.

---

# Definition of Done

A feature or language is considered complete only when:

- All automated tests pass.
- Build succeeds.
- Manual QA is complete.
- Vercel preview is verified.
- Code review is approved.
- No architecture changes were required.
